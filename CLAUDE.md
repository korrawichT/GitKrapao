# GitKrapao

A GitKraken-style Git GUI built with Tauri (Rust + TypeScript), using pnpm.

## Name
- The app is called **GitKrapao** (a pun on GitKraken and กะเพรา): `productName`, `mainBinaryName`, the window title, the page title and user-facing messages.
- The project folder is `D:\gitkrapao` (renamed from `D:\lanes`). Internal names are `gitkrapao` too: the Cargo crate (`gitkrapao`, `gitkrapao_lib`), package.json, the test hook `window.__gitkrapao` and the mock marker `.git/gitkrapao-mock` (`pnpm run mock` still accepts the old `lanes-mock`). Only two things keep the old name `lanes`, on purpose: the localStorage keys (`lanes.*`) and the Tauri `identifier` (`local.lanes.gitgraph`). Never rename them: the identifier picks the WebView data folder, so changing either loses every user's saved settings (hidden branches, solo, column widths, recent repos). `bundle.publisher` is set to `GitKrapao` on purpose: without it Tauri takes the identifier's second part, and Windows "Installed apps" showed the publisher as `lanes`. ("lanes" is also the graph's own word for its columns: `--lanes`, `laneStashes`, `Layout.lanes`.)

## Goal
- The feature that must be best-in-class is the history graph of commits, branches and merges: as beautiful and easy to read as GitKraken's.
- When designing or making UI decisions, weigh graph clarity (lanes, branches, merges) first.

## Graph rendering (src/app.ts)
- Virtualized: the DOM holds only rows near the viewport (`pool`), and the graph is drawn on a viewport-sized `<canvas>`. Never go back to building DOM/SVG for every row.
- Edges are indexed in tiles of 256 rows (`buildTiles`). Per-row state (sel, dim) must be computed from the row index, not from DOM nodes.
- Layout is append-only (`layoutRows`): rows already placed never move when a new page arrives; an edge whose parent is not loaded yet waits in `open`. Any layout change must give identical values whether the history is loaded at once or page by page. (Stash rows are the one exception; see below.)
- Desktop mode uses the order from `git log --date-order` as is (narrower graph than `topoOrder`); `topoOrder` is only for logs pasted in browser mode.
- Every row ↔ pixel conversion goes through `rowOff` (ROW_H while the WIP row shows, else 0): `makeRow`, the canvas top, the `draw()` range, `placeRows` (body height, `moreRow`), `ensureVisible`, `jumpTo` centering, and both sides of `scrollAnchor`/`anchoredTop`. When the WIP row appears or goes away, `placeRows` shifts scrollTop so the same commits stay on screen.
- Lane colors come from the CSS token `--lanes` (one list per theme; the light theme uses darker shades so lines reach 3:1 on a white page). `readTheme` loads it into `PALETTE`/`ON_COL`; `applyTheme` rebuilds rows, panel and card when it changes. Text on a colored fill (node initials, checked-out label, avatars) always goes through `textOn`, which picks dark or white by WCAG contrast.
- `ROW_H` in app.ts must equal `--rowh` in app.css.
- Every theme block sets `color-scheme` (light/dark) and `--scroll`; `:root` has `scrollbar-color: var(--scroll) transparent` (inherited). Without them WebView2 draws white scrollbars on the dark theme. Tested in `contrast.suite.mjs`.
- A row shows its first label plus "+N". Hovering the Branch / tag cell (120 ms) opens `.ref-pop` over the rows below with every label, the first one in place, all stretched to the widest with icons on the right edge; it closes on leave, scroll, `render` and theme change. Graph labels carry `data-g` (index in `c.groups`) so the branch menu acts on the label that was clicked.
- Canvas pixels are not bit-exact even when the same data is redrawn, so never compare layouts by pixels; compare rows (lane, color) and edges.

## WIP row (work_status)
- While the work tree has uncommitted changes, a `// WIP` row sits above row 0 (canvas row -1), joined to HEAD by a dashed line in HEAD's lane. Clicking it (or ArrowUp from row 0) shows the staged/unstaged file card; `sel` is -1 and `wipSel` is true while it is selected. When HEAD is not in the graph (solo without it, or not loaded yet) no WIP node is drawn and the row says "HEAD is not in the graph": a node in some lane would look like it belonged to that branch.
- The toolbar's branch name comes from `S.refs.headRef`, not from labels (solo can leave HEAD unlabelled).
- `work_status` runs `git status --porcelain=v2 -z` with `GIT_OPTIONAL_LOCKS=0` (does not rewrite `.git/index`) and `-c core.fsmonitor=false` (does not start a file monitor). Clean filters the user configured (e.g. git-lfs) can still run, as with any `git status`. `parse_status` has a fixture test.
- Work tree edits do not touch `.git`, so the ref fingerprint cannot see them and `.git/index` must not be added to it (any terminal `git status` rewrites the index, which would turn every poll into a sync). `loadWip` polls on its own: every 4 s, or 8× the last status time if that is longer, skipped while the window is hidden, forced on load, after a sync and on window focus.

## Stash rows in the graph
- Each stash with a loaded base commit is also a row (`stashRow`) above the commit it was made on: a gray box node and a dashed gray line (`color: -1`). They are merged in by committer time with `mergeNew` and are not part of `git log`'s output.
- This is the one exception to append-only layout: `placeStashes` redoes the layout when the set of placed stashes changes (stash list changed, full reload, or a new page brings in a stash's base); it only renames rows when just `stash@{n}` shifted.
- `layoutRows` skips stash rows, so branch lanes and colors are exactly what they would be without stashes; `laneStashes` then gives each stash the first lane right of its base that is free on every row between them. `S.maxLane` must include `S.stashLaneMax`.
- `planSync` marks stash rows as reached (they hang off refs/stash, not branches); otherwise every sync would fall back to a full reload. The toolbar count leaves stash rows out (`S.stashRows`).

## Backend (src-tauri/src/lib.rs)
- `start_history` runs a single `git log` process and reads it to the end in a background thread (so git never holds pack-file handles open on Windows). The UI asks for pages through `history_page(gen, start, count)`; an old `gen` gets `stale`. The stream holds every record read so far, so leaving a repo releases it: `dropRepo` calls `stop_history(gen)` (via `stopHistory`, the newest gen started, once per gen), which kills git, makes `read_log` stop and drop the pipe (a kill may hit only the `git` launcher while the real git keeps writing), and frees the rows. The backend ignores a stop when a newer stream has started (`stop_stream`; the gen is taken under the stream lock), because the stop can reach it after the next `start_history`. A load that finds itself superseded right after `start_history` stops its own stream. Never kill the stream in `start_history` before its `busy` check: a repo that waits for its op keeps its graph and `loadMore`. Tests: `stop_stream_respects_gen`, `read_log_stops_when_asked`.
- Records are split on byte 0x1e before UTF-8 decoding (so Thai characters are never cut in half).
- The fingerprint reads files in `.git` (HEAD, config, packed-refs, refs/, reftable/, logs/refs/stash) instead of spawning git, because each git spawn costs about 200 ms on Windows.
- In desktop mode branch/tag labels come from `list_refs` (for-each-ref + the HEAD file), not from the log's `%D`. Loading and syncing must always use the same source.

## Auto-refresh (syncRepo)
- Poll sees a new fingerprint → `sync_history` asks only for new commits (`git log --stdin`, with the old `^tip`s fed through stdin because repos with many tags exceed the Windows command-line limit) → `planSync` → `applySync`.
- `planSync` must fall back to a full reload whenever it cannot prove the result matches a fresh load: loaded commits disappeared (reset/rebase/deleting an unmerged branch), a removed tip lies deeper than what is loaded, a new commit would land below the loaded rows, or the fingerprint changed while reading.
- Any change here must be tested by comparing the synced result with a full reload (order, lanes, colors, edges, labels) on a test repo whose commits are made with plumbing (`commit-tree`, `update-ref`).
- The Refresh button and Ctrl/⌘ R always do a full reload (the escape hatch when something is wrong).
- `streamPos` is the number of records read from the stream; it differs from `S.commits.length` once commits have come in through sync.

## Tabs (src/tabs.ts, src/app.ts; desktop only)
- `tabs.ts` holds the pure part (no DOM, no backend): `Tab` `{ path | null, name, info?, sel?, err? }`, `loadTabs`/`saveTabs`, `afterClose`, `cycle`, `nth`. `info` (last `open_repo`/`pick_repo` answer), `sel` and `err` live in memory only: `lockKey` is never read from storage.
- Saved in localStorage `lanes.tabs` as `{ tabs: {path,name}[], active }` (empty New tabs are not saved; an empty list means the user closed every tab). With no `lanes.tabs`, boot migrates from `lanes.last`. `lanes.last` is still written (the active repo) so an older build opens it. Never rename either key (see Name).
- Only the active tab's repo is loaded, polled (`syncRepo`, `loadWip`) and given `loadMore`/PR calls; background tabs never call the backend, except that an operation (fetch, switch, create, rename, delete, undo) the user started in a tab keeps running after the tab is left. Leaving a repo (another tab, a New tab, the last tab closed, a failed load, a tab that waits for its op) stops its history stream (`stop_history`, see Backend) and hides its banner (`dropRepo`). `loadWip` keeps its busy mark and next-poll time per request (`wipBusy` is the path): a `work_status` of the repo left behind never holds back or delays the new tab's. A tab switch is a full reload (`showTab` → `dropRepo({ empty: false })` → `loadRepo`); from `dropRepo({ empty: false })` (or the load that follows the `#tabBusy` placeholder) until that load ends, `#tabLoading` shows a spinner in the middle of the graph area (a refresh of a loaded graph shows none). Then `restoreSel` reselects the remembered commit only if it is already in the loaded rows (never pages to find it).
- `loadSeq`: every load, sync and `dropRepo` bumps it; a load that finds `seq !== loadSeq` after any await returns without touching state or showing an error. Activating another tab therefore supersedes a load in flight. `dropRepo` also bumps `openSeq`/`jumpSeq` and sets `streamGen = -1` so a late `open_repo`, jump or page of the old repo lands nowhere. `activateTab` on the already-active tab retries only when its repo failed to load. A load that fails (not `busy`, not `stale`, not superseded) while the graph is not that repo's (another repo, or the `#tabBusy` placeholder) runs `dropRepo()` before `showError`, so the banner stays and `#stats` is cleared, and forgets the repo from recents as a failed open does; a failing refresh of a loaded graph keeps the graph.
- PR lists are cached per repo in `prCache` (a list still loading included), with `prSeq` per path, so going back within `PR_EVERY` does not run `az` again; an answer for a repo that is no longer current goes to its cache entry only. Closing a tab calls `forgetPrs`. Refresh (`force`) always asks again.
- Operations are per tab (see Fetch): `ops` (by `lockKey`) → `RepoOp { kind, pending }`; `tabRunning(t)` is true for every tab of that lock key that has `info` (an `open_repo` answer; linked worktrees share the key), so each shows a spinner and its × is off (`closeTab` refuses, `aria-disabled`).
- While `opHere()` (the active repo has an op) these are off through `opOff()`: Refresh, the recent menu's "Open another repository…" / Ctrl/⌘ O (`pickRepo`), hide/show/solo and "Show all", the Switch, Create, Rename and Delete items (`switchOff`, `createOff`: the running op's `OP_BUSY` text via `opNow`, else `capOff`'s reason), Fetch, syncs and WIP polls. `body.op-running` carries the styling. `capOff()` turns Fetch, Switch, Create, Rename, Delete and Undo off in other repos once `MAX_OPS` run. Other tabs stay free.
- The Undo bar (`#undoBar`, see Rename / delete) belongs to the active tab's repo: `runOp` hides it when any operation starts (Undo's own included), `dropRepo` hides it when the repo is left (another tab, a New tab, the last tab closed, a failed load), and a new delete replaces it. Syncs and reloads of the same repo keep it. A delete that finishes while its tab is in the background shows no bar (only the Output drawer). `updateFetchBtn` turns `#undoBtn` off through `capOff()`.
- A repo that is not on screen when its op runs shows the `#tabBusy` placeholder instead of the graph (`waitForOp`: the backend answers `"busy"`); `RepoOp.pending` keeps the load asked for, and `runOp` runs it when the op ends if that repo is still active. A repo already loaded keeps its graph.
- A result for a repo whose tab is not active is logged in the Output drawer only: no banner, no drawer opening, no load. A failure there sets only `Tab.err` (a dot on the tab, cleared on activation); a later success there clears that key's `opErr`. Activating the tab loads it in full anyway. In the active repo a failure shows the banner, opens the drawer and sets `opErr` (the banner text per lock key), and a later success hides the banner only if it still shows that text. When the active repo waited behind the placeholder, `runOp` shows the failure again after the load (the load's `hideError` would erase it) unless the load failed with its own error.
- Shortcuts (the document `keydown` handler, `preventDefault` so WebView2 does not act on them): Ctrl/⌘ T new tab, Ctrl/⌘ W close, Ctrl Tab / Ctrl Shift Tab next/previous (wraps), Ctrl/⌘ 1–8 that tab, 9 the last. Opening a repo already in a tab (`goToOpen`) activates that tab instead; opening from a New tab or the recent menu fills the active tab (`targetTab`). The `▾` button (`#tabMore`) lists every tab.
- Every per-repo `ask_native` title names the repo (`Fetch — <name>: trust this repository?`, `Switch branch — <name>: …`, `Delete branch — <name>: <branch>`) because the dialog can belong to a tab that is not active. Keep it that way for any new per-repo dialog (the close warning is app-wide and lists repos in its body).
- Strip: ARIA tabs, one tab stop (the active tab), name = repo folder name. Class names start with `tab`; `tab-item`, `tab-x`, `tab-spin`, `tab-dot`.
- Tests: `tests/ui/tabs.suite.mjs` (restore, switching, late answers dropped, selection, New tab, close, shortcuts, `lanes.tabs`/`lanes.last` incl. migrate and gone variants, `stop_history` on New tab and on a tab waiting for its op, WIP per repo, a repo deleted during the session), `tabs-ops.suite.mjs` (per-tab fetch/switch, cap of 3, placeholder, a failure or failing load after the placeholder, background results, worktrees sharing a lock key), `repo-switch.suite.mjs` (rapid opens: newest load wins, PR cache). `tabs-ops` and `repo-switch` also run against the production bundle; `tabs` reads `window.__gitkrapao` and runs on the test bundle only. All use a fake `__TAURI__`, never a real repo.

## Fetch (src-tauri/src/fetch.rs)
- The button is an icon only (`icon-btn ghost`: no background or border until hover; its text is `aria-label` "Fetch" / "Fetching" and the `title` tooltip, which also gives the off reason). With Create branch (`#branchBtn`, see Create) it sits in the middle of the window: `.toolbar` is a grid `minmax(0,1fr) auto minmax(0,1fr)` (not `1fr`, whose min-content minimum lets a long left group push the middle off centre; `.repo-btn` has a max-width so the repo name shrinks with its column) (`.tb-l`, `.tb-mid`, `.tb-r`); at ≤560px the groups become `display: contents` and the old wrapping flex row returns. There is no Open button: a repo opens from the repo name's menu, Ctrl/⌘ O, the empty page or a New tab.
- Manual only: the toolbar button and Ctrl/⌘ Shift F (no background fetch, so no surprise credential popups). One operation (fetch, switch, create, rename, delete, undo) at a time per repo and at most `MAX_OPS` (3) app-wide, both counted in the UI (`ops` by `RepoInfo.lockKey`, `runOp`); the backend only enforces one per repo.
- Command: `git fetch --all --prune --no-prune-tags --no-auto-maintenance --no-recurse-submodules`. Add only flags that turn behaviour off; local branches and tags must never be deleted or overwritten. Never pass `-c` overrides of `core.sshCommand` / `credential.helper` (they would override the user's global config); `GIT_TERMINAL_PROMPT=0` stays.
- Refused before git runs: a `remote.*.fetch` destination outside `refs/remotes/`, `remote.*.mirror`, any file in the legacy `.git/remotes/` or `.git/branches/` folders (`--prune` could then delete local refs).
- Trust: one `git config --show-scope --includes -z --get-regexp` call (`--includes` matters: `--local` alone misses an `include.path`). Keys from local/worktree scope that run programs (ssh/credential/askpass, `hook.*`, `filter.*` smudge/clean/process, an fsmonitor program) or redirect fetch, plus the hook files fetch, a checkout, auto-gc or a push runs (`TRUST_HOOKS`: reference-transaction, post-checkout, post-merge, post-index-change, pre-auto-gc, pre-push), go into a native dialog (`ask_native(app, title, ok, cancel, text)`, Rust side, so page script cannot answer it; the caller names the Cancel button, e.g. "Keep on origin"). `pre-push` is there because deleting a tag on origin pushes; a repo with such a hook is asked once more, and a repo without one keeps its old hash (test `pre_push_is_trusted_without_changing_other_hashes`). One gate for fetch, switch, create, rename, delete and undo (`trust_gate`, one hash per repo): trusting a repo once covers them all; only fetch also asks once about a never-fetched repo, since it contacts the remotes. Exit codes other than 0/1 refuse. Approvals and the allowlist live in `app_data_dir()/trust.json` as SHA-256 hashes (`sha2`, stable across Rust versions); `pick_repo` allowlists its folder, a repo opened from recents asks once.
- `RepoLock` per canonical common dir (`GitDirs.lock_key`, shared by linked worktrees), taken by fetch, switch, create, rename, delete and undo from before any dialog to the end: `repo_fingerprint` returns null and `start_history`/`sync_history` return `"busy"`; the UI pauses polling for that repo, defers a load and syncs once when the operation ends.
- `busy_repos: OpRegistry` (`AppState`) maps lock key → `RunningOp` (kind, repo name, a PID slot the op's git process fills). `running_pids` feeds `kill_tree` on `RunEvent::Exit` and on "Close anyway", so every running tree dies with the app; `close_warning` lists the ops in the native dialog the `CloseRequested` handler (lib.rs `run`) shows first (`closing_prompt` stops a second dialog). Tests: `registry_tracks_each_running_op`, `close_warning_lists_ops_by_repo` in `cargo test --lib fetch`.
- `run_limited` (also under `output_within`) kills the whole process tree on timeout (`taskkill /T`): `git` on PATH is a launcher, and a plain kill leaves the real git, ssh and remote helpers running. The 90 s limit starts when git starts, not when the dialog opens.
- Results (fetch, switch, create, rename, delete and undo) are a `GitResult` (only "busy" is an Err) logged in the Output drawer (last 50, memory only, text via `textContent`); a failure also goes to the banner and opens the drawer only while that repo's tab is active (see Tabs).
- Tests: `cargo test --lib fetch` uses temp repos with a local bare remote and an empty global config (`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM`); the timeout test proves the tree kill with a marker file. UI: `tests/ui/fetch.suite.mjs` with a fake `__TAURI__`.

## Switch branch (src-tauri/src/switch.rs)
- Double-click a branch in the panel or a graph label, or "Switch to …" (first item) in either right-click menu. Off for the checked-out branch, while an operation runs in that repo, or at the cap of `MAX_OPS` operations in other repos (`switchOff` → `capOff`).
- `target` is a full ref. Local: `git switch --no-guess <name>`. Remote `refs/remotes/<remote>/<name>` (longest matching remote, names may contain `/`): if no local `<name>`, `git switch -c <name> --track <full ref>`; if one exists, switch to it, then `git merge --ff-only <full ref>` only when it is merely behind (same, ahead or diverged: left as is, the summary says why). A branch already checked out is not switched again (that was a silent no-op: "develop to develop"). Names are checked with `check-ref-format --branch` and `show-ref --verify` first.
- Never `--force`, `--discard-changes` or `--merge`: uncommitted work is never lost. Changes git can carry go along; when git refuses ("would be overwritten/removed by checkout") a native dialog lists the files and offers Stash and switch (`git stash push --include-untracked -m "GitKrapao: before switching to <name>"`, then the same switch). The stash is not popped; a failure after stashing says the work is in stash@{0}.
- Same `RepoLock`, `run_limited` and Output drawer as fetch; 5 min limit (a kill can leave the work tree half updated, so the summary says to check `git status`). Before any step it passes the same `trust_gate` as fetch: hooks, filters and an fsmonitor from the repo's own config need approval; a filter set up in the user's global config (git-lfs) is theirs and is not asked about. Every step runs with `SAFE_CONFIG` (`-c maintenance.auto=false -c gc.auto=0 -c submodule.recurse=false`, off-switches only, left out of the drawer's command text): a merge would otherwise start auto-gc, and recursing would run a submodule's hooks and config, which the trust check never sees.
- Tests: `cargo test --lib switch` (temp repos: tracking branch created, behind → fast-forwarded, diverged → unmoved, carried vs. blocked changes, Cancel keeps everything, Stash includes untracked files, trust asked before a repo hook runs and shared with fetch, no auto-gc after a fast-forward, no submodule recursion, bad targets, timeout). UI: `tests/ui/switch.suite.mjs`.

## Create branch / tag (src-tauri/src/create.rs, src/refname.ts)
- Right-click a commit row (`eventRow`, which also selects it) or a graph label: "Create branch" / "Create tag" (`createEntries`; desktop only, never on the WIP row or a stash row). In the label menu they come after the label's own items, so "Switch to" stays first. Off while an operation runs in the repo or at the cap (`createOff`). Over text selected in the row itself the WebView's own menu (Copy) shows instead; a selection elsewhere does not matter.
- The toolbar's Create branch button (`#branchBtn`, icon only: the logo's trunk and one branch in `currentColor`) opens the same dialog at `branchTarget()`: the selected commit, else HEAD's row (WIP row, a stash row, or a stash or PR card shown → HEAD). Off with "No repository open" (Fetch too) on a New tab, through `createOff()`, or "No commit to branch from" when neither is loaded; `updateBranchBtn` runs from `updateFetchBtn`, `select`, `selectWip`, `render` and on the button's pointerenter/focus (a sync that changes no label renders nothing), because the target follows the selection; a click reads the target afresh. In Windows High Contrast the ghost buttons get a `ButtonText` border.
- The dialog is a `<dialog>` (`#createDlg`, `showModal`: the page behind is inert). It keeps the commit's full hash and the repo's `lockKey`, never a row index (a sync can move rows); a submit whose repo is no longer the active one does nothing. While it is open the document `keydown` handler only closes it on Esc and still blocks Ctrl/⌘ R and F5; no other shortcut runs. The padding sits on the form, so a click on the dialog element itself is on the backdrop; it closes the dialog only when the press started there too (`downOnBackdrop`), not after selecting text in a box and letting go outside.
- `closeCreate` resets `createFor` at once. Chromium fires a dialog's 'close' event on an animation frame (in the headless UI tests there are none, so it may come at any later time or never): a late one is ignored while the dialog is open again.
- Names are checked as they are typed: `nameProblem` (git's check-ref-format rules; a leading "-"; "HEAD" and "@" alone, which every git command reads as HEAD; and names Windows cannot store, since refs are files there: `" < > |`, a part ending in ".", device names such as con, nul, aux/x, com1.txt) and `nameClash` against `S.refs` (the same name in any letter case, which is one file on Windows and macOS, or a folder clash such as feat and feat/x). The backend checks again with git before anything runs: `valid_name` (plain `check-ref-format refs/heads/<name>`, not `--branch`, which reads "@{-1}" as the previous branch; "-x", "HEAD" and "@" refused), `windows_unsafe` (the same Windows rules as `nameProblem`: "a./b" would be the file of a packed "a/b"), `taken`, and `at`.
- `taken` compares every existing branch (or tag) without case, for any letter, not only ASCII: next to a packed ref (after a clone or gc) git itself lets "Ärger" in beside "ärger", and on Windows the new file then stands in for the packed ref, which in effect moves it. If the list cannot be read, nothing is created.
- `at` must be a full hash (40 or 64 hex digits) that resolves to a commit (`rev`): a short hex string can also be a ref name (a branch "abcd1234"), and nothing that looks like an option reaches git.
- Same `RepoLock`, `trust_gate` (op "Create branch" / "Create tag": a new ref runs the reference-transaction hook), `Steps` with `SAFE_CONFIG`, native dialog titles naming the repo, and Output drawer as switch. In the UI it is an operation like the others (`runOp('branch' | 'tag')`, `OP_BUSY` titles, also on the `#tabBusy` placeholder; "Switching…" only when it checks out). Never `-f`: a taken name is refused and no existing ref is moved or deleted.
- Branch: `git branch <name> <hash>` (no upstream). With "Switch to the new branch" (on by default) it then runs `switch_in` under the same lock (the stash question included) and reports both steps as one `GitResult` (`then_switch`; its exit code is the switch's, so a switch that never ran shows "not run"). A switch the user cancelled keeps the new branch and is not `cancelled` (that means nothing changed); only a failed switch is a failure.
- Tag: always `--no-sign` (signing runs gpg.program, which the repo's own config can name and the trust check does not list; tag.gpgSign would also turn a lightweight tag into a signed one). With message text it is annotated (`-a --cleanup=whitespace -m`; the default cleanup drops lines that start with "#"), else lightweight. Keep the `-a`: with a message but without it, tag.forceSignAnnotated signs even under `--no-sign`. The message is trimmed.
- Nothing is pushed.
- Tests: `cargo test --lib create` (temp repo: created where asked with HEAD unmoved and no upstream, create and switch, a blocked switch cancelled or stashed, lightweight and annotated tags, never signed with tag.gpgSign, tag.forceSignAnnotated and gpg.program set, bad and taken names including "@{-1}", names Windows cannot store (refused before git runs; whole parts only, so console and com10 are fine), a packed ref in another case (ASCII and not), `at` that is not a full commit hash, the merged result, Thai names, trust asked before a reference-transaction hook runs, a hung hook stopped). UI: `tests/ui/create.suite.mjs` (fake `__TAURI__`: both menus, the WebView menu over selected row text, the dialog, validation, invoke arguments, operation state, Output and banner, Esc, Cancel, the backdrop, F5, a late 'close' event) and `tests/ui/refname.suite.mjs` (the name rules, checked against git 2.42).

## Rename / delete branch, delete tag (src-tauri/src/refedit.rs)
- Local refs only; nothing is renamed or deleted on a remote, and there is no rename for tags. Terms are in GLOSSARY.md.
- Menus (desktop only): a local branch in the panel (leaf, after Copy) or a graph label with a local branch (before the Create items) gets "Rename branch" and "Delete branch" (`branchEntries`); a graph tag label gets "Delete tag", "Copy tag name", then the Create items (`pillTag`, `tagEntries`; a tag label had no menu before, and it still has none in browser mode). Remote-only labels and branches get nothing new. Off through `createOff` (an operation in the repo, or the `MAX_OPS` cap); Delete on the checked-out branch is off with "The checked-out branch cannot be deleted" (`branchEntries` reads `S.refs.headRef`, not the label's `g.head`, and compares with `sameRef`, without letter case; the panel's `is-head` uses `sameRef` too), and the backend refuses it too (`checked_out`).
- `exact(repo, ns, name)`: reads `for-each-ref --format=%(objectname) %(refname)` and needs a byte-exact match. Never `show-ref` / `rev-parse` a name the page sent: on Windows git opens a loose ref file whatever the letter case, so `Feat` would act on `feat`. Rename and delete refuse unless the name matches exactly.
- `case_sibling`: another branch whose name equals this one without case (any letter) but not byte for byte, e.g. a packed `feat` beside a loose `FEAT`. Rename and delete refuse before any question: on Windows git reads both as one file, so `git branch -D feat` would delete FEAT's commit too. Delete tag checks it as well (a packed `v1` beside a loose `V1`: deleting one removes both on Windows, and Undo would bring back only one). A sibling in a folder (`Feat/x` next to `feat/y`) is not covered (create has the same limit). Every case-insensitive comparison goes through `fold_case` (create.rs, `to_lowercase`: any letter), the one `taken` uses.
- `checked_out(repo, name)`: this worktree's HEAD (`symbolic-ref -q HEAD`; exit 1 is a detached HEAD) and every `branch refs/heads/…` line of `git worktree list --porcelain` (this worktree included) that equals `refs/heads/<name>` without case. On Windows HEAD `refs/heads/Feat` resolves through the file of `feat` (`git checkout Feat` does that), and git's own checks compare bytes, so `branch -D feat` / `-m feat x` would leave that HEAD on a branch that no longer exists. Delete refuses on any match: here "The checked-out branch cannot be deleted.", elsewhere "Branch <name> is checked out in another worktree, so nothing was deleted. …". Rename refuses only a match that is not byte-exact (here: "HEAD names this branch as <X> (another letter case); …", elsewhere: "Another worktree has this branch checked out as <X> …"); a byte-exact HEAD follows the rename. A git error refuses ("Could not read the worktrees, …").
- Rename: `exact`, `case_sibling`, `checked_out`, a new name equal to the old one refused, `valid_name`, `windows_unsafe`, `taken`, `trust_gate("Rename branch")`, then `git branch -m -- <from> <to>` (the upstream, reflog and HEAD follow; the checked-out branch can be renamed). A name that `taken` finds to be the branch itself in another case is refused with "Only the letter case changes; Windows stores both names as one file." (`nameClash(name, kind, names, self)` says the same in the dialog and leaves the own name out of the clash list, so `feat` → `feat/x` passes). No confirm dialog: the rename dialog is the confirmation. No Undo for rename.
- Rename dialog: `#createDlg` again (`createFor.mode = 'rename'`: `.c-at`, `#cMsgRow` and `#cSwitchRow` hidden, title "Rename branch", button "Rename", the old name selected, Go off while unchanged), so Esc, F5, the backdrop and the `lockKey` check on submit work as for create. `openCreate` unhides what rename hid.
- `unreachable`: `git rev-list --count <tip> --not --exclude=<full ref> --all <every stash commit>` (60 s limit, `COUNT_LIMIT`). `--all` covers branches, remote-tracking branches, tags, HEAD, `refs/stash` and the HEADs of linked worktrees (pinned by a test), but `refs/stash` is only `stash@{0}`; older stashes live in its reflog, so each commit of `git stash list --format=%H` is passed after `--not` too. More than 500 stashes (`MAX_STASHES`, Windows command line) or a git error or timeout gives `None`. A tag is counted from the commit it peels to (`rev`).
- The question: "Delete branch <name> (<short>)?" (tag: "Delete tag …"). With a count above 0, `lost_text` appends "N commits will no longer be on any branch. Undo brings them back; after that only via git reflog / git fsck." (singular wording for one). With `None`: "GitKrapao could not count the commits only this branch keeps; some may no longer be on any branch. …". The "only via git reflog / git fsck" clause is true because `git branch -D` also drops the branch's reflog; keep the wording honest.
- Confirmations are native (`ask_native` via `OpCtx.confirm`, so page script cannot answer). Titles `"{op} — {repo}: {tail}"`: `Delete branch — <repo>: <branch>`, `Delete tag — <repo>: <tag>`, `Delete tag — <repo>: also delete on origin?`; the trust dialog is `{op} — <repo>: trust this repository?` with the op's first word on OK (Rename / Delete / Undo). Cancel on the delete question or the trust dialog is `cancelled`; "Keep on origin" is not.
- Delete branch order: `exact` (the tip), `case_sibling`, `checked_out`, `branch_config` (the `branch.<name>.*` entries of `config --local -z --list`; the prefix must match exactly and the rest have no dot, since `branch.feat.x.remote` belongs to a branch `feat.x`), `unreachable`, `trust_gate("Delete branch")`, confirm, then `exact` again: a tip that moved while the dialog was open refuses ("moved while the dialog was open; nothing was deleted"). Then `git branch -D -- <name>` (git drops the config section). `--` because a ref named `-x` can exist.
- Delete tag: `exact` gives the object (the tag object for an annotated tag), `case_sibling`, `trust_gate("Delete tag")`, confirm, then `git update-ref -d refs/tags/<name> <object>`: with the old value git refuses if the tag moved meanwhile (no second `exact`).
- Origin question: only after the local delete, and only when `git remote` lists a remote named `origin` (another name never asks). The text shows every push URL (`remote get-url --push --all origin`: a push goes to each), each through `no_userinfo` and then `sanitize`: `user:password@` is cut from any `scheme://` authority (it ends at the first `/` only, as for git, so a password may hold `?` or `#`; up to its last `@`), and a lone `user@` too for http(s), where it is often a token; scp-style `git@host:path` and paths stay. When any URL is not a server (`get-url` already applies insteadOf / pushInsteadOf; `network_url`: http(s), ssh, git or scp-style `host:path`; a path, share, `file://` or `helper::` URL is not), it warns that pushing there runs that repository's own hooks (pre-receive, update, post-receive), which the trust check never saw: the repo's config names origin, so this is the one place the user decides about them. It also says teammates keep their copy and Undo does not bring it back on origin. "Delete on origin" runs `git push --no-signed --no-recurse-submodules origin --delete refs/tags/<name>` with a 90 s limit (`PUSH_LIMIT`; `--no-signed` because signing runs `gpg.program`, which the repo's config can name; the push runs `pre-push`, hence the trust gate). `GIT_TERMINAL_PROMPT=0` as always. An origin that never had the tag counts as success (newer git exits 0 with "deleting a non-existent ref", older servers say "remote ref does not exist"; `onOrigin` is false). That text is read only with one push URL (with several, another may have had the tag), and the push runs with `LC_ALL=C` so it is English. A failed or timed-out push is `ok: false` with the local tag already gone and `deleted` kept, so Undo is still offered.
- `GitResult.deleted?: DeletedRef { token, kind, name, short, onOrigin }` is set whenever the local ref was deleted (after a failed push too) and never otherwise. `short` is the branch tip, or the commit the tag peels to. The page gets only the token: what to restore (`Deleted`: kind, name, object id, the config entries) stays in `AppState.undo` (`UndoStore`: one entry per lock key, a global counter, a new delete replaces the old entry). `take` needs the key and the token to match and removes the entry; a stale or foreign token leaves the valid entry alone. It is put back (`put_back`, only if the slot is still empty) when `restore_ref` refuses before it writes anything (name taken, object gone, trust cancelled, git could not start), and when `update-ref` failed without a timeout and `exact` still finds no ref (update-ref is atomic: a folder `<name>/` in the way, a stale `.lock`); that result has `exitCode` null although git ran (the Output drawer says "not run", git's stderr is kept). Never after a timeout or once the ref was written.
- `restore_ref(path, token)`: `taken` (case-insensitive, any letter) refuses a name someone else has used meanwhile, `cat-file -e` explains a missing object ("git gc removed it"), `trust_gate("Undo delete")`, then `git update-ref -m "GitKrapao: undo delete" <ref> <object> <zero oid>`; the zero old value makes git refuse if the name appeared since. A branch's `branch.<name>.*` entries are re-added with `git config --local --add -- <key> <value>` in order (upstream included) unless something set that section meanwhile; if the config cannot be read the result is `ok: false` and says the upstream was not restored; a key saved without a value comes back as `true`. An annotated tag comes back as the same tag object (message intact). Local only: the bar says so when `onOrigin` is set. `git gc --prune` makes it impossible.
- Hidden and solo: `followRef(paths, from, to|null)` rewrites (rename) or removes (delete) the exact `refs/heads/<from>` entries of `lanes.hidden` and `lanes.solo`; folder entries (ending in `/`) stay. `repoPaths(info)` gives the path plus every tab with the same `lockKey` (linked worktrees), also tabs in the background. When a list changed, `runOp` does `hiddenGen++`, `renderSide()` and a full `loadRepo({ keep: true })` instead of `syncRepo()`. Known limits: a tab restored at boot and never activated has no `info`, and a worktree not open as a tab has no entry, so their lists keep the old name. Undo does not put a hidden or solo entry back.
- `runOp(kind, call, { switching?, done? }): Promise<GitResult | null>`: `OpKind` adds `rename`, `delBranch`, `delTag` and `restore` with `OP_BUSY` titles ("Renaming branch…", "Deleting branch…", "Deleting tag…", "Restoring…"; also on `#tabBusy`). `done(r, info)` runs right after `logOp` in the active tab or not; it returns whether the lists changed.
- Undo bar: `#undoBar` (`role=status`, `#undoMsg`, `#undoBtn`, `#undoClose`) under the banner, text via `textContent`: "Deleted branch|tag <name> (<short>)", plus " here and on origin. Undo restores it here only." when `onOrigin`. Shown by the delete's `done` only when `r.deleted` is set and the repo is still active (so also with the error banner after a failed push). It keeps the token and the lock key; Undo does nothing if the active repo changed. Hides on ×, when any operation starts, and in `dropRepo` (see Tabs). A restore the backend refused before writing (`!ok`, `exitCode` null, not timed out, also "busy" and a refused `update-ref`) shows the bar again, since the token is still valid; a timeout or a run that wrote the ref and then failed (the settings) does not.
- Tests: `cargo test --lib refedit` (temp repos, a local bare origin, a recording `Fixture` in `testutil.rs`: rename keeps upstream, reflog and HEAD; `feat` → `feat/x`; case-only, taken (loose and packed), invalid and Windows-unsafe names refused; trust asked before a hook and a hung hook stopped; merged branch asks plainly; the count matches `rev-list` and ignores commits a tag, remote branch, stash (also `stash@{1}`), detached HEAD or a linked worktree's HEAD reaches; Cancel keeps everything; the checked-out branch and a branch in another worktree refused before any question; HEAD (here or in a linked worktree) naming the branch in another letter case refuses delete and rename, a byte-exact worktree HEAD follows a rename; a moved tip not deleted; names matched exactly; a case sibling refused (branches and tags); lightweight and annotated tags; origin yes / keep / no origin / origin without the tag; credentials cut from the origin URLs (`no_userinfo` cases and the dialog text); pre-push through trust and never signed; a failed or hung push keeps `deleted`; restore with upstream, same tag object, a taken name never overwritten, a cancelled restore keeps the token, an `update-ref` git refused (folder clash, stale lock) keeps it and a timed-out one uses it up, tokens per repo and single use, restore after gc explained). `cargo test --lib fetch` has `pre_push_is_trusted_without_changing_other_hashes`. UI: `tests/ui/refedit.suite.mjs` (also on the production bundle; fake `__TAURI__` with three tabs, one a linked worktree: every menu, the rename dialog and its checks, invoke arguments, busy titles, the bar and its token, a refused restore (also a refused `update-ref`; not after a timeout or a later failed step), a failed push, Delete off when HEAD names the branch in another letter case (panel and the label box), replace and hide rules, hidden/solo followed in every tab of the repo and not in other repos, `start_history` instead of `sync_history`, background results) and the self / case-only cases in `tests/ui/refname.suite.mjs`.

## Column widths

- `graph: null` = wide enough for every lane but at most a third of the window (`graphColW`; followed on window resize), so a repo with many branches never pushes the message and date columns off screen; double-click resets to it, a dragged width wins. `msg: null` = fill the remaining space. Test: `tests/ui/graph-width.suite.mjs`. If the Graph column is narrower than the lanes, the canvas is cut and fades at the edge (`graphColW()` is used instead of `S.graphW` when drawing).

## Left panel (renderSide)
### Branches
- Lists every branch, split into LOCAL / REMOTE (grouped per remote); names containing `/` become folders. It reads `S.refs` (the same ref snapshot as the graph labels, not the loaded commits) in both modes.
- Clicking a branch → `jumpTo` selects the tip and centers it. If the tip is not loaded yet (hollow dot) it keeps calling `loadMore` until it is.
- Ahead/behind comes from `branch_tracking` (for-each-ref `%(upstream:track)`), requested separately after load/sync because it can be slow for branches that diverged long ago. The fingerprint includes `.git/config` so `git branch -u` updates the counts. Browser mode counts over the graph against the branch of the same name on origin.
- It is an ARIA tree (one tab stop, Up/Down/Left/Right, Enter). Collapsed folders are kept in `lanes.sideClosed`, the width in `lanes.sidew`; Ctrl/⌘ B shows/hides the panel (`lanes.side`). On narrow screens (≤900px) the panel floats over the graph.
- Panel classes start with `sb-`. Never use class names that collide with the graph's, e.g. `.head` (that once broke the rows).

### Hiding branches
- Eye icon on hover, the H key, "Show all", and the right-click menu (`#ctxMenu`: Hide/Show + Copy branch name on panel branches, Hide on folders/remotes, Hide + Copy on a graph branch label, which hides every ref in that label). The menu follows the eye button's rules (not the checked-out branch, not during solo). Elsewhere in desktop mode the WebView's own right-click menu is off, except in text boxes and over selected text. Saved per repo in localStorage `lanes.hidden` as full ref names or prefixes ending in `/` (a whole folder or remote).
- The backend turns them into `git log --exclude=<name> --branches --exclude=<name> --remotes --tags HEAD` (`rev_args`). `--exclude` takes names without refs/heads/, applies only to the next --branches/--remotes, and its `*` also matches `/`. Commits that a visible ref still reaches stay in the graph. The checked-out branch cannot be hidden.
- Labels and sync tips come from `visibleRefs(refs, hidden)`; the panel uses all of `S.refs`. Hiding/showing does a full reload (`hiddenGen` makes a load/sync that ran with the old list reload again). Test by comparing commit count and order with `git log` using the same `--exclude` set.
- Browser mode rebuilds a ref snapshot from `%D` (`refsFromDec`) and filters commits itself in `showBrowser`. Never overwrite `c.dec` (that once made hidden refs vanish from the panel).

### Solo
- Target icon on hover and the S key; "Exit solo" in the bar. Saved per repo in `lanes.solo` (same entry format as hidden). Solo wins over hidden; eye buttons are hidden while it is on.
- `rev_args` then walks only `--glob`s: a folder is `--glob=refs/heads/x/*`; an exact ref brackets one letter of heads/remotes (`--glob=refs/[h]eads/x`) because a glob without wildcards gets `/*` appended, and the branch name itself is never bracketed (wildmatch compares bytes, so Thai names would not match). A missing branch matches nothing instead of failing. Unit-tested against real git.
- The solo walk has no tags and no HEAD, so sync tips come only from soloed refs (`walkRefs`); labels may add tags (`labelRefs`). Using HEAD or a tag tip as `^exclude` would drop commits that a soloed branch later merges in. If no soloed ref exists any more, solo turns itself off on the next load.

### Stashes and pull requests (desktop only)
- STASHES come from `list_stashes` (`git stash list`). Clicking a stash or PR shows its card in the detail panel (`detailFor` = commit / stash / pr) and moves the graph to the related commit with `select(i, { detail: false })`, which does not replace the card. The card survives syncs and goes away when the stash is dropped or the PR leaves the list (`refreshCard`).
- The fingerprint includes `logs/refs/stash` because `git stash drop` does not touch `refs/stash`.
- PRs come from Azure DevOps through `az repos pr list` with the account signed in via `az login` (the app stores no token). origin is used first (`parse_azure_remote` handles dev.azure.com, visualstudio.com and SSH URLs). They are fetched again every 5 minutes, after a sync if older than 30 seconds, and on every Refresh. az errors are read from stdout and stderr together (az writes its questions to stdout).
- `open_url` only opens https links on dev.azure.com / *.visualstudio.com.
- The PR UI cannot be tested in the real WebView by replacing invoke (`__TAURI__` is frozen and non-configurable). Use headless Edge with a fake `__TAURI__` loaded before app.js (as `tests/ui/webview-menu.suite.mjs` does). Test real az calls with an empty `AZURE_CONFIG_DIR` so the user's account is never used.

## File diff view (file_diff)
- Clicking a file in a commit, stash or WIP card shows its diff over the graph (`.diff` inside `.center`); `#wrap` stays mounted underneath so its scroll and virtualization survive. Unified or split, changes only or full file (`lanes.diff`), J/K (or ]/[) between files, Esc back. While it is open the graph keys are off; a branch/stash/PR click, a hash link and switching repos close it.
- Backend kinds: `commit` (also stashes, `--diff-merges=first-parent` like the card), `staged`, `unstaged`, `untracked`. Always `--literal-pathspecs` (a file named `[a].txt` must not match `a.txt`), `--no-ext-diff --no-textconv --no-color`, both paths of a rename, `GIT_OPTIONAL_LOCKS=0` and `core.fsmonitor=false`. Output is capped at 4 MB without splitting a UTF-8 character (`cap_text`).
- Untracked files are read directly (`untracked_patch`) as an all-added diff: relative paths only (no `..`, no absolute, no `\` or `:`), canonicalized and checked to stay inside the repo, symlinks shown as their target and never followed, 2 MB cap, NUL in the first 8000 bytes = binary.
- Conflicted files show a message instead of a combined (`diff --cc`) diff.
- `parseDiff` handles CRLF, "\ No newline at end of file", binary files and hunk-less changes (mode only, pure rename, empty files). Paired removed/added lines get word marks from their common start and end. At most 20,000 lines are rendered. Line classes are `t-add`/`t-del`/`t-ctx`: plain `.add`/`.del` are the global +/− text colors and once turned whole lines green and red.
- Commit and stash diffs are cached (100); work tree diffs are not. While a work tree diff is open, every WIP poll re-reads it with `loadDiff(true)` (quiet: no "Loading…", errors keep what is shown, redrawn with the scroll kept only when the patch changed), because editing an already modified file does not change git status or the WIP signature. A poll never cancels a load in flight (`dfBusy`), or a slow file would keep restarting. `panelFiles` is what the card lists now; `dfKey` re-finds the open file after the card is redrawn (`markDiffRow`).
- Tests: `file_diffs_against_real_git` (cargo) and comparing the app's +/− line counts with `git --numstat` for commit, stash and WIP files.

### Syntax colors (src/highlight.ts)
- Our own small lexers (no third-party code; the CSP stays `script-src 'self'`). The language comes from the file name (`Syntax.lang`; the old side of a rename uses `oldPath`); unknown types stay plain. Families: JS/TS, JSON, C#, Java/Kotlin, Go, Rust, C/C++, Python, Ruby, PHP, shell, PowerShell, SQL, CSS/SCSS, HTML/XML (csproj, xaml, svg…), YAML, INI/TOML/.env, Markdown, Dockerfile.
- Lexers return `[start, end, class]` ranges in UTF-16 offsets, never HTML. `codeHtml` escapes every piece and only emits classes in `Syntax.CLASSES` (as `sx-*`). Word marks count code points; `unitAt` converts them so an emoji before a change does not shift the mark. Pieces are split at both token and mark edges so tags never cross.
- Lexing runs per side: one lexer over the old side (context + removed lines) and one over the new side (context + added lines), with state carried line to line (block comments, multi-line strings, open tags). Unified context lines use the new side; split view's left column uses the old side. Never lex removed and added lines as one stream: a removed line that opens a comment would color the added lines.
- In Changes mode a hunk can start inside a docstring or code fence, so `loadDiff` also fetches the whole-file diff (context 1000000, same cache key as Full file) in parallel and waits for both before rendering (a later re-render would reset the scroll). `wholeTokens` lexes it once and `highlightDiff` gives each line the colors of its old/new line number when the text matches. Added, deleted and untracked files already arrive whole and skip this. If the whole diff is truncated or over the caps, lexer state resets at every hunk instead.
- File contents are untrusted: regexes are sticky/anchored with no nested quantifiers, lines over 2,000 characters stay plain, and coloring stops after 20,000 lines or 2 M characters.
- Colors are `--sx-*` tokens (light and both dark blocks). Tests: text of every rendered line equals the patch; multi-line comment state; hunks starting inside a Markdown fence and a Python docstring; old/new side separation (unified and split); markup in a file renders as text with no elements created; C#/Python/JSON samples; a 20,000-line file in full.

## Commit details (commit_detail)
- Fetched when a commit is selected, via `git show --raw --numstat -z` (merges compared with the first parent). Always pass `--no-ext-diff --no-textconv` so a repo's config can never make it run external programs.
- `parse_detail` reads paths by position (not by content). Unit tests use real output in `src-tauri/tests/fixtures/` (`cargo test --lib`).
- The JS side waits 100 ms before fetching (for fast arrow-key browsing) and caches 300 commits.

## TypeScript
- The UI is TypeScript (`src/app.ts`, `highlight.ts`, `ipc.ts`, `types.ts`). esbuild bundles it into one IIFE at `dist/app.js` and does not check types; `tsc` only checks (`noEmit`). Run `pnpm run typecheck` before calling a change done.
- `strict` + `noUncheckedIndexedAccess`. No `@ts-ignore` / `@ts-expect-error`; no `any` except at a parse boundary, with a comment. A `!` or `as` needs the reason it holds (a length check, `has()` before `get()`, an element in index.html), written next to it when it is not obvious.
- Data from Rust is typed by `src/bindings/*.ts`, generated by ts-rs (a dev-dependency only; `#[cfg_attr(test, derive(ts_rs::TS), ts(export))]` on each struct sent to the UI, `u64`/`i64` fields marked `ts(type = "number")`). Changing such a struct: `cargo test --lib` regenerates the bindings, commit them; `pnpm run check:bindings` fails on a forgotten one. `.gitattributes` keeps `src/bindings` LF so regenerating is a no-op on Windows.
- Every Rust command is called through `invoke` in `src/ipc.ts`; its argument types live in the `Commands` map there.
